# --- grpc 0.5.0-beta.1 advisories, all first patched in grpc 1.0.0 ---
# This app runs an internal gRPC server (GRPC.Server.Supervisor); it is reachable only from
# inside the cluster by sibling Semaphore services, not from the internet. The fix is grpc
# 1.0.0 — a breaking major shared across the monorepo, tracked as a coordinated migration
# (see ee/audit/.mix-audit.txt), not a security-patch bump.
#
# RCE via :erlang.binary_to_term in GRPC.Codec.Erlpack.decode/2 (critical). Requires a server
# that registers the Erlpack codec and accepts application/grpc+erlpack; no app in this repo
# registers any custom codec (repo-wide grep for Erlpack/codecs: is empty), so the vulnerable
# decode path is unreachable.
GHSA-grp7-v8xh-rj7h
# Decompression bomb in GRPC.Compressor.Gzip.decompress/1 (high) — fires on frames arriving
# at a server with grpc-encoding: gzip; availability-only.
GHSA-6ccx-9c9f-327w
# Unbounded request-body accumulation in read_full_body/3 (high) — the server request read
# loop; availability-only.
GHSA-q8gf-9rvj-gmgj

# cowlib arrives transitively via the cowboy/gun stack pinned by grpc; bumping it forces the
# same grpc 1.0.0 stack migration. This app terminates no SPDY, emits no SSE and builds no
# cookies from user input, so the affected encoders/decoders never see attacker data.
# cow_http_te excessive allocation (high)
GHSA-32p9-57cr-4x65
# cow_spdy:inflate/2 decompression bomb via crafted SPDY frame (high)
GHSA-84f2-rp86-235p
# CRLF injection enabling SSE event splitting (moderate)
GHSA-hv23-4qp7-8c8r

# cowboy 2.7.0 — unbounded buffer accumulation in multipart header parsing causes DoS
# (GHSA-jfc2-q6qh-g5x8, high), patched in cowboy 2.15.0. Version pinned by the grpc adapter
# stack. This app parses no multipart HTTP request bodies (no multipart hits in lib/).
GHSA-jfc2-q6qh-g5x8

# decimal 2.0.0 — unbounded exponent DoS in Decimal.new (GHSA-rhv4-8758-jx7v, moderate).

GHSA-rhv4-8758-jx7v
