# --- grpc 0.11.5 advisories, all first patched in grpc 1.0.0 ---
# All four are server-side, and auth never starts a gRPC server: there is no
# `use GRPC.Server` and no GRPC.Server.Supervisor anywhere in lib/, and no
# start_server config. grpc is used purely as a client (GRPC.Stub via
# Auth.GrpcClient / Auth.FeatureClient) against internal backend services.
# Same posture as front (see front/.mix-audit.txt); ee/rbac differs because it
# does serve gRPC (see ee/rbac/.mix-audit.txt). The real fix is grpc 1.0.0, a
# breaking major shared across the monorepo, tracked as a coordinated
# migration rather than a patch bump.
#
# RCE / atom-table exhaustion via :erlang.binary_to_term in
# GRPC.Codec.Erlpack.decode/2 (critical). Needs a server that registers the
# Erlpack codec and accepts application/grpc+erlpack; auth registers no codec
# (grep for Erlpack, GRPC.Codec and `codecs:` across lib/ and config/ returns
# nothing) and serves no gRPC endpoint.
GHSA-grp7-v8xh-rj7h
# Decompression bomb in GRPC.Compressor.Gzip.decompress/1 (high), fired by
# frames arriving at a server carrying grpc-encoding: gzip. auth only decodes
# responses from internal services, which are not attacker-controlled.
GHSA-6ccx-9c9f-327w
# Unbounded request-body accumulation in read_full_body/3 (high) — the server
# request read loop only.
GHSA-q8gf-9rvj-gmgj
# Path bindings overridable by query string and request body (high). Requires
# HTTP transcoding of gRPC path bindings, which auth does not expose.
