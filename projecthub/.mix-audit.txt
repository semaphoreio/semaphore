# --- grpc 0.5.0 advisories, all first patched in grpc 1.0.0 ---
# projecthub runs an internal gRPC server (Projecthub.Api.GrpcServer); reachable only from inside
# the cluster by sibling Semaphore services, not from the internet. Bumping to grpc 1.0.0 is a
# breaking major that splits the grpc package into grpc/grpc_server/grpc_core across ~20 services
# in the monorepo (already suppressed the same way in front, guard, notifications, zebra, ee/audit,
# ee/rbac, hooks_processor); not viable as a same-day fix. Tracked as a coordinated migration in
# an internal grpc-1.0 migration follow-up - this is the interim, not the fix.
#
# UNREACHABLE - RCE / atom-table exhaustion via :erlang.binary_to_term in
# GRPC.Codec.Erlpack.decode/2 (critical). projecthub registers no `codecs:` option on any
# GRPC.Server, so the server's codec list defaults to [GRPC.Codec.Proto] (grpc 0.5.0,
# lib/grpc/server.ex); find_codec/2 rejects application/grpc+erlpack before decode/2 is ever
# reached. Erlpack is opt-in and has zero usages anywhere in this monorepo.
GHSA-grp7-v8xh-rj7h

# rejects any grpc-encoding header before GRPC.Compressor.Gzip.decompress/1 is called.
