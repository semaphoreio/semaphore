# mix_audit allowlist for hooks_processor.
#
# Exposure baseline used by every rationale below: hooks_processor has two listeners —
# an internal gRPC server (InternalApi.RepoProxy.RepoProxyService on :50050, consumed only
# through the internal-api-urls configmap, no ambassador/ingress mapping) and an HTTP
# health-check (Plug.Router, GET-only, no Plug.Parsers) on :4000. Webhook payloads arrive
# via RabbitMQ, not HTTP. Nothing is internet-facing.

# --- grpc 0.9.0 advisories, all first patched in grpc 1.0.0 ---
# grpc 0.9.0 -> 1.0.0 is a major upgrade (API changes, cascades to gun/cowboy and the
# generated .pb.ex stubs) tracked separately as the real fix; same acceptance as ee/audit.
#   GHSA-grp7-v8xh-rj7h (critical) — RCE via Erlpack codec calling :erlang.binary_to_term/1.
#     Not exploitable: the cowboy handler resolves codecs only among those registered on the
#     server, and the 0.9.0 default is [Proto, WebText, JSON] (deps/grpc/lib/grpc/server.ex:127).
#     No `codecs:` option anywhere in lib/, so application/grpc+erlpack is rejected with
#     "No codec registered" and binary_to_term is never reached.
#   GHSA-6ccx-9c9f-327w (high) — unbounded gzip decompression. Not exploitable: compressors
#     default to [] (server.ex:128) and neither Endpoint nor Server sets any, so a
#     grpc-encoding: gzip request is rejected ("Not found compressor registered") before inflate.
#   GHSA-q8gf-9rvj-gmgj (high) — unbounded request body accumulation in read_full_body/3.
#     Reachable, internal-only: requires an in-cluster caller; availability-only, one pod,
#     supervisor restarts.
#   GHSA-mwr4-5g34-j5cq (high) — path bindings overridable via query/body. Not exploitable:
#     bindings exist only under HTTP/JSON transcoding, which is opt-in
#     (http_transcode defaults false, server.ex:129) and never enabled in lib/.
GHSA-grp7-v8xh-rj7h
GHSA-6ccx-9c9f-327w
GHSA-q8gf-9rvj-gmgj
GHSA-mwr4-5g34-j5cq

# protobuf 0.13.0 — unbounded recursion in embedded-message decoding (GHSA-rv48-qqj5-crxg,
# high; fixed 0.16.1). Walked the full type graph of the vendored internal_api modules
# (425 messages): the only cycle is InternalApi.RBAC.Role (inherited_role/maps_to), which
# hooks_processor never decodes from attacker-controlled input — it appears only in
# responses from the internal rbac service. The RepoProxy server request types are acyclic,
# so no inbound payload can force unbounded recursion. Fix lands with the pb regeneration
# that accompanies the grpc 1.0.0 migration.
GHSA-rv48-qqj5-crxg
